# LAIM kriteria selector

Нода подтверждения определения КМ при подключении версии агента. Повторного выбора формулы, чтения DOCX, переопределения baseline и вызовов LLM здесь нет.

## Входы и выход

| Порт | Содержание |
|---|---|
| `monitoring_metric` | Кандидат `laim-monitoring-metric.v3` от адаптера |
| `run_context` | Ожидаемые `agent_ci` и `solution_version` |
| `measurement_review` | Подтверждение точного определения; без него кандидат недоступен |
| `validated_monitoring_metric` | Определение для сохранения и регулярных прогонов |

Формат подтверждения:

```json
{"decision":"approved","definition_id":"<SHA-256 кандидата>","reviewer":"<проверяющий>","approved_at":"2026-09-05T12:00:00+03:00"}
```

Проверяющий сверяет единицу оценки, рубрику, домен и направление шкалы, границу дефекта, необходимые свидетельства, профиль извлечения и baseline с первичной корзиной. Исправления вносятся в `onboarding_plan` адаптера и повторно компилируются; нельзя просто поменять поле уже подтверждённого определения.

`measurement.py` — единый валидатор структуры, исполнимости и подтверждения v3. Его самодостаточные копии используются производителями и потребителями. SHA-256 включает версию решения, рубрику, формулу, baseline, профиль и хэши артефактов; исключены только поля состояния и подтверждения.

`computed` возможен только при правильном подтверждении, принадлежности агенту/версии и `baseline.reconciliation=match`. Человек не может этим подтверждением обойти арифметическое расхождение. Неизвестные версии контракта, неполное определение и чужое подтверждение дают явную ошибку; отсутствие подтверждения — `not_computable`.

Проверяющий и время — аудит доверенного процесса платформы, а не механизм аутентификации. Хранение и права изменения подтверждения обеспечивает платформа.

Зависимостей Python нет. Удалены `metric_spec`, `metric_dataset`, LLM-настройки, ручная колонка КМ и входы повторного чтения отчётов. В регулярном контуре используется сохранённый `validated_monitoring_metric`.

python3 -m pytest -q
